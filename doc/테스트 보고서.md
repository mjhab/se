1. 테스트 보고서 개요

본 문서는 팀 프로젝트에서 설계한 모임 장소 추천 서비스 Moi-Me(모이미)를 대상으로 작성한 테스트 보고서이다. 본 프로젝트는 실제 구현이 완료된 상태가 아니므로, 본 보고서는 실행 결과 중심의 보고서가 아니라 요구사항과 주요 기능을 기반으로 한 테스트 설계 문서로 작성하였다.

테스트의 목적은 사용자가 모임을 생성하고, 참여자의 출발지를 입력한 뒤, 이동 시간과 조건을 바탕으로 공정한 장소를 추천받고, 투표 또는 주최자 확정을 통해 최종 장소를 결정하는 흐름이 요구사항에 맞게 동작하는지 검증하는 것이다.

테스트 대상 시스템

2.1 시스템 개요

Moi-Me는 여러 명이 만날 때 각자의 출발지, 이동 수단, 모임 목적, 예산, 최대 이동 시간 등을 반영하여 모임 장소 후보를 추천하고, 투표를 통해 최종 장소를 결정할 수 있도록 돕는 서비스이다.

2.2 주요 기능

F1. 모임 생성
주최자가 모임 이름, 목적, 일정, 조건을 입력하여 모임을 생성한다.

F2. 참여자 초대
링크 또는 앱 초대를 통해 참여자가 모임에 참가한다.

F3. 출발지 입력
참여자는 현재 위치 또는 직접 입력으로 출발지를 설정한다.

F4. 이동수단 설정
대중교통, 도보, 자가용 등 이동수단을 선택한다.

F5. 장소 후보 추천
각 참여자의 이동 시간과 모임 조건을 바탕으로 후보 장소를 추천한다.

F6. 필터 적용
카테고리, 예산, 최대 이동 시간 등의 조건으로 후보를 제한한다.

F7. 투표
그룹투표, 익명모드, 독재자모드 중 하나로 장소를 결정한다.

F8. 최종 장소 확정
투표 결과 또는 주최자 선택에 따라 최종 장소를 확정한다.

F9. 공유 카드 생성
확정된 장소, 시간, 참여자 정보를 카드 형태로 공유한다.

F10. 모임 기록 및 리포트
과거 모임 장소와 이동 기록을 저장하고 확인한다.

3.2 테스트 제외 범위

실제 지도 API 연동 정확도

테스트 전략

4.1 테스트 관점

본 프로젝트의 테스트는 다음 관점으로 설계하였다.

단위 테스트
개별 기능 또는 로직의 정상 동작을 확인한다. 출발지 검증, 필터 조건 검증, 투표 계산 등에 적용한다.

통합 테스트
여러 모듈 간 데이터 흐름을 확인한다. 모임 생성, 초대, 출발지 입력, 장소 추천 흐름에 적용한다.

시스템 테스트
사용자 시나리오 전체 흐름을 확인한다. 모임 생성부터 최종 장소 확정까지의 전체 흐름에 적용한다.

인수 테스트
사용자가 요구한 기능이 충족되는지 확인한다. 실제 사용 시나리오 기반으로 검증한다.

회귀 테스트
수정 후 기존 기능에 영향이 없는지 확인한다. 리뷰 반영 후 주요 테스트 케이스를 다시 확인한다.

4.2 테스트 데이터 선정 기준

정상 데이터
사용자가 일반적으로 입력하는 올바른 데이터이다.
예: 정상 주소, 정상 모임명, 유효한 예산

비정상 데이터
시스템이 예외 처리해야 하는 잘못된 데이터이다.
예: 빈 출발지, 잘못된 링크, 권한 없는 확정 요청

경계 데이터
조건의 경계에 있는 데이터이다.
예: 참여자 1명, 최대 이동 시간 30분 제한, 예산 0원

대량 데이터
성능과 안정성을 확인하기 위한 데이터이다.
예: 참여자 30명, 후보 장소 100개

테스트 환경 및 전제 조건

테스트 대상: Moi-Me 서비스 설계 산출물 및 Figma 프로토타입
구현 상태: 실제 구현 전 단계
테스트 방식: 테스트 설계 및 예상 결과 기반 검증
테스트 도구: GitHub, Issue 또는 Pull Request 리뷰, Figma 프로토타입
테스트 결과 표기: Pass / Fail / Not Executed
공통 전제: 사용자는 앱 또는 링크를 통해 모임에 접근할 수 있다고 가정한다.

주요 테스트 시나리오

6.1 모임 생성 및 초대 시나리오

주최자가 모임 이름, 날짜, 목적을 입력한다.
시스템은 모임 정보를 저장하고 초대 링크를 생성한다.
참여자는 링크를 통해 모임에 참가한다.
시스템은 참여자를 모임 구성원 목록에 추가한다.

6.2 장소 추천 시나리오

모든 참여자가 출발지를 입력한다.
각 참여자가 이동수단을 선택한다.
시스템은 후보 장소별 예상 이동 시간을 계산한다.
시스템은 이동 시간 편차가 작고 조건에 맞는 후보를 우선 추천한다.
사용자는 추천 후보를 확인한다.

6.3 투표 및 장소 확정 시나리오

주최자가 투표 방식을 선택한다.
참여자는 후보 장소 중 하나에 투표한다.
시스템은 투표 결과를 집계한다.
주최자는 최종 장소를 확정한다.
시스템은 공유 카드를 생성한다.

8.1 추천 후보 산출 로직 의사 코드

recommendPlace(group, filters):
if group.memberCount < 2:
return Error("2명 이상 필요")

for member in group.members:
    if member.startLocation is empty:
        return Error("출발지 입력 필요")

candidates = searchCandidatePlaces(filters.category)

for candidate in candidates:
    calculateTravelTime(member.startLocation, candidate.location)
    calculateFairnessScore(candidate)

    if candidate.maxTravelTime > filters.maxTravelTime:
        remove candidate
    if candidate.budget > filters.maxBudget:
        remove candidate
    if candidate.category not in filters.category:
        remove candidate

if candidates is empty:
    return Error("조건에 맞는 장소 없음")

sort candidates by fairnessScore
return top candidates
