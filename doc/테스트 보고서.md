1. 테스트 보고서 개요

본 문서는 팀 프로젝트에서 설계한 모임 장소 추천 서비스 Moi-Me(모이미) 를 대상으로 작성한 테스트 보고서이다. 본 프로젝트는 실제 구현이 완료된 상태가 아니므로, 본 보고서는 실행 결과 중심의 보고서가 아니라 요구사항과 주요 기능을 기반으로 한 테스트 설계 문서로 작성하였다.

테스트의 목적은 사용자가 모임을 생성하고, 참여자의 출발지를 입력한 뒤, 이동 시간과 조건을 바탕으로 공정한 장소를 추천받고, 투표 또는 주최자 확정을 통해 최종 장소를 결정하는 흐름이 요구사항에 맞게 동작하는지 검증하는 것이다.
---------------------------------

2. 테스트 대상 시스템
2.1 시스템 개요

Moi-Me는 여러 명이 만날 때 각자의 출발지, 이동 수단, 모임 목적, 예산, 최대 이동 시간 등을 반영하여 모임 장소 후보를 추천하고, 투표를 통해 최종 장소를 결정할 수 있도록 돕는 서비스이다.

2.2 주요 기능
구분	기능명	설명
F1	모임 생성	주최자가 모임 이름, 목적, 일정, 조건을 입력하여 모임을 생성한다.
F2	참여자 초대	링크 또는 앱 초대를 통해 참여자가 모임에 참가한다.
F3	출발지 입력	참여자는 현재 위치 또는 직접 입력으로 출발지를 설정한다.
F4	이동수단 설정	대중교통, 도보, 자가용 등 이동수단을 선택한다.
F5	장소 후보 추천	각 참여자의 이동 시간과 모임 조건을 바탕으로 후보 장소를 추천한다.
F6	필터 적용	카테고리, 예산, 최대 이동 시간 등의 조건으로 후보를 제한한다.
F7	투표	그룹투표, 익명모드, 독재자모드 중 하나로 장소를 결정한다.
F8	최종 장소 확정	투표 결과 또는 주최자 선택에 따라 최종 장소를 확정한다.
F9	공유 카드 생성	확정된 장소, 시간, 참여자 정보를 카드 형태로 공유한다.
F10	모임 기록/리포트	과거 모임 장소와 이동 기록을 저장하고 확인한다.

6. 주요 테스트 시나리오
TS-01. 모임 생성 및 초대 시나리오
주최자가 모임 이름, 날짜, 목적을 입력한다.
시스템은 모임 정보를 저장하고 초대 링크를 생성한다.
참여자는 링크를 통해 모임에 참가한다.
시스템은 참여자를 모임 구성원 목록에 추가한다.
TS-02. 장소 추천 시나리오
모든 참여자가 출발지를 입력한다.
각 참여자가 이동수단을 선택한다.

시스템은 이동 시간 편차가 작고 조건에 맞는 후보를 우선 추천한다.
사용자는 추천 후보를 확인한다.
TS-03. 투표 및 장소 확정 시나리오
주최자가 투표 방식을 선택한다.
참여자는 후보 장소 중 하나에 투표한다.
시스템은 투표 결과를 집계한다.
주최자는 최종 장소를 확정한다.
시스템은 공유 카드를 생성한다.

8. 화이트박스 테스트 설계

실제 소스 코드가 구현되지 않았기 때문에, 핵심 로직인 장소 후보 추천 로직을 대상으로 가상의 제어 흐름을 설정하고 화이트박스 테스트를 설계하였다.

8.1 추천 후보 산출 로직 의사 코드
recommendPlace(group, filters):
    if group.memberCount < 2:
        return Error("2명 이상 필요")

    for member in group.members:
        if member.startLocation is empty:
            return Error("출발지 입력 필요")

    candidates = searchCandidatePlaces(filters.category)

    for candidate in candidates:
        calculateTravelTime(member.startLocation, candidate.location)
        calculateFairnessScore(candidate)

        if candidate.maxTravelTime > filters.maxTravelTime:
            remove candidate
        if candidate.budget > filters.maxBudget:
            remove candidate
        if candidate.category not in filters.category:
            remove candidate

    if candidates is empty:
        return Error("조건에 맞는 장소 없음")

    sort candidates by fairnessScore
    return top candidates

12. 결론

본 테스트 보고서는 실제 구현이 완료되지 않은 상태에서 작성되었지만, 요구사항과 주요 사용 시나리오를 기반으로 정상 데이터, 비정상 데이터, 경계 데이터, 대량 데이터를 포함한 테스트 케이스를 설계하였다. 특히 모임 장소 추천 서비스의 핵심 기능인 출발지 입력, 후보 장소 추천, 투표, 최종 장소 확정, 공유 카드 생성을 중심으로 테스트 항목을 구성하였다.

테스트 설계 과정에서 단순히 정상 동작만 확인하는 것이 아니라, 출발지 누락, 후보 장소 없음, 권한 없는 확정 요청, 익명모드 정보 노출 가능성 등 실제 사용 과정에서 발생할 수 있는 예외 상황을 함께 고려하였다. 또한 팀원의 리뷰를 반영하여 테스트 케이스의 예상 결과를 더 구체화하고, 결함 보고서와 변경 이력을 추가하였다.

따라서 본 문서는 구현 전 단계에서 시스템의 품질을 점검하고, 추후 구현 및 테스트 수행 시 기준으로 활용할 수 있는 테스트 설계 산출물이다.
