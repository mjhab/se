# 프로젝트 관리 계획서

## 1. 서론

### 1.1 목적 및 범위

본 문서는 (프로젝트명) 프로젝트의 전반적인 개발 계획을 정의하고, 프로젝트 수행 시 기준이 되는 관리 지표를 제공하는 것을 목적으로 한다.
본 문서는 프로젝트 개요, 개발 계획, 팀 구성, 품질 관리, 개발 환경, 산출물, 리스크 관리 등을 포함한다.

### 1.2 프로젝트 개요

* 프로젝트명: (프로젝트명)
* 프로젝트 설명: (예: 약속 장소 추천 서비스 / 스터디 관리 시스템 등)

### 1.3 프로젝트 목표

* 핵심 기능 구현
* 사용자 편의성 향상
* 정해진 기간 내 프로젝트 완료

### 1.4 용어 정의

* API: 응용 프로그램 간 상호작용을 위한 인터페이스
* DB: 데이터를 저장하고 관리하는 시스템

---

## 2. 개발 계획

### 2.1 개발 방법론

본 프로젝트는 Agile 기반의 Scrum 방법론을 사용한다.
이는 요구사항 변경에 유연하게 대응하고, 팀원 간 협업을 강화하기 위함이다.

### 2.2 WBS (작업 분할 구조)

* 요구사항 정의
* 설계
* 개발
* 테스트
* 배포

### 2.3 개발 활동

* Sprint Planning: 스프린트 계획 수립
* Daily Scrum: 일일 진행 상황 공유
* Sprint Review: 결과물 검토
* Sprint Retrospective: 개선점 도출

### 2.4 개발 일정

* 1주차: 요구사항 정의
* 2~3주차: 기능 개발
* 4주차: 테스트 및 수정

## 3. 팀 구성

### 3.1 팀 구조

본 프로젝트는 수평적인 협업 구조를 기반으로 진행된다.

### 3.2 역할 및 책임

* 팀장: 프로젝트 총괄 및 일정 관리
* 팀원1: 프론트엔드 개발
* 팀원2: 백엔드 개발
* 팀원3: 데이터베이스 관리

---

## 4. 품질 관리

### 4.1 미팅 계획

* 주 1회 정기 회의 진행
* 필요 시 추가 회의 진행

### 4.2 변경 사항 관리

* 기능 변경 시 팀원 간 협의를 통해 결정한다.
* 변경 사항은 문서로 기록하여 관리한다.

### 4.3 산출물 관리

* 모든 산출물은 GitHub를 통해 버전 관리한다.
